# Web BDD harness

Mirrors the Gherkin + step structure from
[`apps/mobile/integration_test`](../../../mobile/integration_test/) so the two
suites read the same way.

## Running

```bash
# Default: all BDD scenarios except @known-issue
pnpm test:bdd

# Smoke only (still excludes @known-issue)
pnpm test:bdd:smoke

# Critical only
pnpm test:bdd:critical

# All scenarios including @known-issue (will fail until the issues land)
pnpm test:bdd:all

# Mobile viewport runs (iPhone 14)
pnpm test:bdd:mobile

# Re-generate the spec files from .feature files (rarely needed —
# Playwright config does this automatically before each run)
pnpm test:bdd:gen
```

## Layout

```
tests/bdd/
├── features/                F01_…feature, F02_…feature, …
├── steps/                   common.steps.ts, header.steps.ts, …
├── fixtures.ts              test/Given/When/Then exports + helpers
├── .features-gen/           generated by bddgen — gitignored
└── README.md                this file
```

## Feature numbering

| Feature | What it covers |
|---|---|
| F01_guest_browsing | Home / discover / content / creator / sitemap / robots smoke |
| F02_header | Header CTA discipline (one of each, no redundancy) |
| F03_join_cta_count | At most one visible Join button per page |
| F04_positioning_copy | Brand voice — no "travel-only" leak |
| F05_signin_modal | Contextual sign-in modal opens on action gates |
| F06_navigation | Section deep-links + 404 status |

## How it works

`playwright-bdd` reads `.feature` files, generates `.spec.ts` files in
`.features-gen/`, and dispatches steps to the impls in `steps/`.

The harness uses [`tests/mock-api-server.mjs`](../mock-api-server.mjs) so SSR
fetches don't need the real Hono API + DB. The dev server is launched with
`E2E_API_BASE_URL=http://localhost:9876` which wins over `.env.local` thanks
to the precedence check we added in
[`apps/web/src/lib/api-client.ts`](../../src/lib/api-client.ts) — without
this you would silently hit your real API.

## Known issues (`@known-issue` tagged scenarios)

These are written and runnable but skipped by default while we settle the
underlying bug.

### `@next-15-not-found-status`

Two F06 scenarios assert that `/content/<missing>` and `/<vertical>/<missing>`
return HTTP **404**. They currently return **200** with the not-found body
because Next.js 15's response status is committed in `generateMetadata`
before the page render's `notFound()` fires. Mitigated in production via
`noindex` on
[`apps/web/src/app/not-found.tsx`](../../src/app/not-found.tsx).

### `@next-dev-hydration-race`

Two F05 scenarios click the SaveButton / comment-stub and assert the modal
appears. Reproduces only in `next dev` + Playwright — the click dispatches
before React binds the synthetic-event handler in dev-mode SSR streaming.
Manual click in the browser works correctly. Will likely be unblocked by
running BDD against `next start` of the production build.

## Tag conventions (mirrors mobile)

| Tag | Meaning |
|---|---|
| `@smoke` | Must pass on every push |
| `@critical` | Subset of smoke; can never regress |
| `@guest` `@auth` `@modal` `@cta` `@nav` `@header` `@copy` `@seo` `@footer` | Domain |
| `@web` `@mobile` `@all-viewports` | Viewport scope |
| `@known-issue` + `@<reason>` | Skipped by default; documented exception |
