Screen 03 · Discover

Discover · browse, search, filter

Three states of the Discover tab. Home feed is "what's fresh for me." Discover is "I'm looking for something specific." Default is a browse grid (8 verticals, 6 marked "soon"). Tapping search opens an overlay with personal recent + trending. Tapping the filter icon opens a bottom sheet with orthogonal facets (budget, duration, difficulty, etc.).

Key design notes
Browse first, search second. The default Discover state is browse — user sees 8 categories and handpicked collections without typing anything. Search is one tap away but not the default. Compare to Google, where search is the only surface — here, browsing is deliberately surfaced because users don't always know what they're looking for.

6 of 8 verticals are "soon" in MVP. Travel and Stories ship. The other 6 verticals render dimmed with a coral "soon" tag. Tapping a soon tile adds the user to that vertical's waitlist (DD-002) and shows a toast: "We'll notify you when {vertical} goes live."

Collections are algorithmic for MVP, manual for V1. The three collections shown ("New in Travel", "Worth the drive from Pune", "Under ₹5,000") are generated from templates + user location + user's interest signals, cached per user per day. V1 adds an admin panel where the platform team can override with manually curated collections. (DD-014 amendment)

Facets are orthogonal to the taxonomy. The filter sheet shows Budget, Duration, Group size, Difficulty — these are NOT sub-categories of the vertical tree. They're filter dimensions that cut across any content. A user can filter by "budget ₹2k–5k + duration 3–5 days + moderate difficulty" without specifying a vertical. (DD-006)

Trending is V1, not MVP. The "Trending this week" section in the search overlay is marked V1 because it requires the top_searches_7d materialized view + enough search volume to be meaningful. In MVP, the search overlay shows only personal recent searches + the 5 seeded placeholder suggestions.
