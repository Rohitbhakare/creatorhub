Screen 02b · location picker and nearest-neighbor fallback

Current location · mandatory step with honest fallback

Location is captured as a mandatory step during onboarding (between OTP and category selection). No home city / viewing city split — users have a single current city they can change anytime. When a city has no content, the home feed falls back through a nearest-neighbor waterfall (exact city → 200km → 500km → India-wide) and shows an honest banner telling the user what's happening.

DD refs: DD-009, DD-010, DD-011
SRS refs: ONB-FR-006, DISC-FR-025 through DISC-FR-029

Location is mandatory · no skip
The header shows "Step 2 of 5" but has no "Skip" button, unlike other onboarding steps. Location is the foundation of the home feed's "Near you" section and the nearest-neighbor waterfall — we cannot show a useful feed without it. The user can pick their city from the list OR tap "Use my current location" for GPS permission.
No home-city / viewing-city split · just "current location"
Earlier drafts had a dual abstraction — "home city" (persistent) and "viewing city" (temporary override). Rohit rejected this as over-engineering. Users have exactly one current location. If they travel from Pune to Manali, they change their location from Pune to Manali. When they come back, they change it back. One field, one mental model. (DD-009)
"Popular in India" · not a tier-based list
Earlier we considered a tier system (Tier 1 / Tier 2 / Tier 3 cities). Rejected — it's both technically fragile and subtly condescending. Instead, we seed the initial list with the top 5 cities by population, and the full dataset (~2500 cities from GeoNames) is searchable from the input field above. Every city is equal. A user in Shirdi or Kohima types their city and gets the same treatment as one in Mumbai.
Engineer note · PostGIS from Week 1
Enable the PostGIS extension on Supabase on day one of the build. Seed the cities table from the GeoNames India dataset (cities with population ≥ 5000, ~2500 rows). Each row has geography(POINT, 4326) for PostGIS ST_DWithin queries. Do NOT build materialized views — runtime ST_DWithin is fast enough for MVP content scale.

The honesty banner is the entire point
"Nothing in Shirdi yet — showing trips from Nashik, Aurangabad, Pune." This single sentence is worth more than a thousand polished UI elements. Users in smaller cities have been gaslit by every major Indian app for years ("Showing results from all of India!") — we tell them the truth about why they're seeing what they're seeing. Sub-copy: "We'll notify you as soon as creators publish from Shirdi."
Distance badge on each card
Every card in a fallback state shows the distance from the user's current city — "Nashik · 80 km", "Aurangabad · 120 km", "Pune · 185 km". The user can instantly decide whether something is worth the drive. This is only shown when the user is in fallback mode — for exact-match cities, cards show city name without distance.
Nearest-neighbor waterfall · 4 levels
1. exact city match (content.starting_city_id = user.current_city_id)
   if count < 5: fall through
2. ST_DWithin(content.point, user.point, 200_km)
   if count < 5: fall through
3. ST_DWithin(content.point, user.point, 500_km)
   if count < 5: fall through
4. popular_in_india (any Indian city)
Each level has its own banner copy. Level 4 says "Nothing nearby yet · showing popular across India." The home feed remembers which level matched so cards render the correct distance badge.
Coral pin in the location chip
The location chip in the top bar uses the single coral pin icon. This is one of the 5 allowed uses of coral per DD-013 — the icon that represents "where I am." The chip is tappable: tapping it opens the location picker as a bottom sheet, letting the user update their current city without going back to onboarding.
GPS refresh rules
If the user has granted location permission, we refresh the GPS point on app foreground if >1 hour has passed since last refresh. We do NOT refresh on every app open (battery drain). If the new GPS point is >50km from the current users.current_city_id, we show a non-intrusive toast: "Looks like you're in Nashik now. Update your location?" with Yes / No Thanks. We never auto-change the user's city without consent.
