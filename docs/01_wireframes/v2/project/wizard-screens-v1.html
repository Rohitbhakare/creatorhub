  1. Q1 · SE Days storage: Reuse itinerary_days with parent_type='experience', no spots. ✓ One day-builder mental model; one pagination pattern.
  2. Q2 · Day-count edit after publish: Warn with diff ("Day 4 + Day 5 will be deleted"), require confirm. ✓ No silent data loss.
  3. Q3 · Cancellation policy: Three options for M1 (Flexible / Moderate / Strict). Non-refundable added in M2 with Razorpay automation. ✓
  4. Q4 · Freemium default: ON for Day 1 only on paid itineraries — predictable conversion driver. ✓

4 NEW New decisions from review v1

Founder added 4 new requirements. Recommendations below — confirm and they become locked. Tags like Q11 on the screens point to where each lives visually.

  1. Q9 · Edit after publish — what's editable? Yes, allow editing post-publish. Recommended scoping (keeps marketplace integrity): Posts: everything editable freely.
    Itineraries: all fields; price changes apply to NEW buyers only (existing get grandfather price); day-count change uses Q2 warn-and-confirm flow.
    Events: description/photos/capacity freely; date/venue/cancellation changes notify all RSVPs via push + WhatsApp.
    Scheduled experiences: any departure WITH bookings is locked (date can't move, capacity can only grow); description/photos/meeting-point/inclusions freely; price changes apply only to future departures with no bookings yet.
    Locked across all: content type, vertical, sub-category (would invalidate Discover surfaces and search index).
  2. Q10 · Duplicate / copy: Clone everything except status (→ draft), dates (cleared for SE/event), reviews / bookings / engagement (all zero); title gets "(copy)" suffix; new contentId. Action lives in Studio content card overflow menu and on the published detail screen for the owner. Useful for SE creators running same trip seasonally.
  3. Q11 · Delete published content: Two paths based on whether bookings exist. No bookings / RSVPs: hard delete with confirm. Removed from Discover, search, follower feeds.
    Has bookings / RSVPs: soft delete (status → archived); existing buyers / RSVPs keep access and download rights; content disappears from Discover, search, creator profile; no new buyers possible. Confirmation copy explains the difference.
  4. Q12 · No draft until first save: Today wizard_shell_screen.dart:62-65 POSTs a stub draft on initState regardless of whether the user types anything. Result: every wizard open creates an orphan row in studio_content. Defer draft creation until first auto-save tick (when isDirty=true) OR explicit Next button press. If the user closes without entering data, just context.pop() — no API call, no draft, no studio-list pollution. Existing close-with-data flow keeps prompting "Save & exit / Discard".

What this captures vs current implementation

These wireframes target the gaps surfaced in the parallel-Claude wizard chat. The list below cross-references the design moves to the existing Flutter code so review is concrete.

Step structure changes

  • Post: 3 → 2 steps. Today's BasicsStep + PostMediaStep collapse into a single Compose surface with Fraunces body editor + 6-icon toolbar + inline image insert.
  • Event: 5 → 4 steps. The locked-free _FreeEventPricingStep in wizard_shell_screen.dart goes away; cancellation moves into Details.
  • Itinerary: 6 → 5 steps. Cover image folds from MediaStep into BasicsStep.
  • Scheduled experience: 5 → 7 steps. Today's single ExperienceDetailsStep (which holds dates + meeting + cancellation) splits into Days (text), Departures, Meeting point, plus an Overview step before them. The new Days step is a brand-new screen — no equivalent exists.

Bug surfaced + fixed in this redesign

  • Reveal hours data loss: _revealHours in experience_details_step.dart:34 is collected on chip tap but never sent in _saveExperienceDetails payload (wizard_shell_screen.dart:268-284). The DB column meeting_points.exact_shared_hours_before defaults to 24, so 12h/48h selections silently die. The new Meeting point step explicitly persists it.

Monochrome moves

  • Type picker: create_tile_config.dart:29-60 hardcodes peach/sky/sage/lavender icon fills + 4 colored foregrounds. New picker uses --sunken backgrounds + --ink icons, with self-routing copy ("I'm taking travellers somewhere") instead of generic descriptors.
  • Spot stop chips: spot_editor_sheet.dart _stopTypeChipColor returns 5 colors today. New chips: surface + hairline + ink icon for 4 of 5 types; only Overnight uses coral-tint + coral border.

Already shipped — preserved as-is

  • InclusionsExclusionsBlock dual chip lists (15 max each, preset suggestions) — used unchanged on Itinerary & SE Pricing.
  • PricingStep take-home math (Base → +GST → Buyer pays → −Platform −TDS → coral take-home) — restyled into split "Buyer pays" / "You earn" cards but logic identical.
  • Auto-save service + Saved/Saving/Save-failed pill in top bar — unchanged.
  • Soft-auth sheet (6 triggers, including publish) — already complete.

New backend touches required

  • Reveal hours plumbing: add exact_shared_hours_before to PUT /api/v1/experiences/:id and the wizard payload.
  • SE day text: add experience_days table OR reuse itinerary_days minus spots. Founder to decide.
  • T&Cs consent record: CRT-FR-022 wants version + timestamp per publish, not just a boolean. Likely a tnc_consents table or columns on each content row.
  • Google Places proxy: server-side autocomplete + place-details endpoint (key never touches client). Spot editor depends on it.

Open questions for review need answer

  1. SE Days storage: new experience_days table, or reuse itinerary_days with parent_type='experience' and no spots? Recommendation: reuse to keep the day-builder mental model consistent and avoid two pagination patterns later.
  2. Day count immutability after publish: if a creator changes day count post-publish, existing day descriptions on Day 4/5 silently drop. Block edit, warn, or allow with confirm? Today's wizard is silent.
  3. Cancellation policy strings: "Flexible / Moderate / Strict" — three options or four (add "Non-refundable")? Razorpay refund automation only supports the three at M2.
  4. Freemium default ON for itineraries: matches Substack's free-preview default, but our ARPU model assumes most chapters are paid. OK to default ON, or default OFF with a recommendation banner?
  5. SE meeting point on review screen: show the public area only, or both public + private with a lock badge (so the creator can verify what their travellers will see vs what's hidden)? Recommendation: both, clearly labeled.
  6. Spot creator-note as required vs optional: design pushes the note as the visually dominant card element with a coral star ("most-read"). Make required, or strongly suggested? Required raises the bar for paid itineraries but kills 1-tap spot adds.
  7. Multi-image post inline insert: design shows ＋Photo in toolbar. Limits today: max 5 images per post (CLAUDE.md). Render inline at insertion point, or as a gallery row at the end?
  8. Preview watermark: needed everywhere (4 review screens), or only on paid content where the publish-vs-draft distinction matters more? Recommendation: everywhere — consistent affordance.

Out of scope for this epic

  • Real Google Maps embed — the public meeting-point map is a static-tinted area; real Maps SDK ships when GCP key is procured.
  • SE pricing variants (early-bird, group discounts) — single per-person price for now.
  • Video uploads — image-only across all wizards in M1.
  • AI helper chips in basics (ai_helper_chip.dart exists but minimal) — keep as-is.
